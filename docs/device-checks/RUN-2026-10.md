# Device run-through — weekend of 2026-10-04

One ordered pass on the Fire TV Stick (AFTSS, Fire OS 7.7.1.6) that covers DESC-005, DESC-006, DESC-008, the My list and
Described screens (PR #12), the crossfade (kit `setVolume`) and the decoder check from decision 0001.
The per-ticket files (DESC-005.md … DESC-008.md) have more background. This file is the order to run them in.

**Time:** about 3½ hours. Setup 45–75 min (the first release build is the slow part), checks about 2 h, VoiceView 20 min.

**How to work through it**

- Tick each box. Write numbers and notes on the blank lines. Copy them into the results table at the end.
- `adb exec-out screencap` gives a black image on this stick (friction 2026-09-26). Watch the TV and listen.
  For visuals, take a phone photo or video of the TV.
- Remote buttons are written in bold: **Select**, **Back**, **Menu**, **Home**, **Play/Pause**, ▲ ▼ ◄ ►.
- If a step fails, note what you saw and keep going, unless the step says stop.
- Run everything from the main checkout at `~/hackathon/described`.

**Stream under test:** `https://dco7qa0c4m1pw.cloudfront.net/published/sintel-90-150-r2/master.m3u8`
(Sintel 1:30–2:30, 60 s, 1920×818 H.264 High L4.0, 9 description cues, **no extended cues**).
Because the clip is 60 s long, the timings below differ from the per-ticket files, which were written for longer clips.

**Not covered this weekend**

- DESC-007 Extended mode (pause, speak, resume). This stream has no extended cues. It needs a DESC-010 title later.
- **Hear a sample** on Title. It needs `DescriptionCue` rows, and the fresh database below has none, so the button
  does not show. That is expected here.
- DESC-009 Settings and full VoiceView pass: use `docs/a11y/voiceview-checklist.md` separately.

### 0.5 Put the titles in the catalog (terminal B)

There is no admin "publish" call. You create each title with `POST /admin/titles`, then mark it published in SQL.
The pipeline is not run, so nothing is paid.

First, six filler titles. They only exist so the Described grid has more than one row. Do not play them: their streams do
not exist. Create them **before** Sintel, so Sintel is the newest title and fills the Home hero.

```sh
set -a; source .env; set +a
for i in 1 2 3 4 5 6; do
  curl -s -X POST localhost:4000/admin/titles -H "x-admin-token: $ADMIN_TOKEN" -H 'content-type: application/json' \
    -d "{\"slug\":\"grid-test-$i\",\"name\":\"Grid test $i\",\"license\":\"test\",\"attribution\":\"Test row.\",\"sourceS3Key\":\"none\"}"; echo
  sleep 1
done
```

Check the poster exists before you point the title at it:

```sh
curl -sI https://dco7qa0c4m1pw.cloudfront.net/published/sintel-90-150-r2/art/poster.jpg | head -1
curl -sI https://dco7qa0c4m1pw.cloudfront.net/published/sintel-90-150-r2/art/hero.jpg | head -1
```

If both say `200`, keep the `posterKey` and `heroKey` fields below. If not, delete those two fields from the JSON.

```sh
curl -s -X POST localhost:4000/admin/titles -H "x-admin-token: $ADMIN_TOKEN" -H 'content-type: application/json' -d '{
  "slug":"sintel-90-150-r2","name":"Sintel","year":2010,"license":"CC-BY 3.0",
  "attribution":"Sintel © Blender Foundation, CC-BY 3.0. Described by Described.",
  "synopsis":"A girl named Sintel searches the snowy mountains for the baby dragon she raised.",

  "posterKey":"published/sintel-90-150-r2/art/poster.jpg","heroKey":"published/sintel-90-150-r2/art/hero.jpg"}'; echo

/opt/homebrew/opt/postgresql@14/bin/psql -h /tmp -U postgres described -c \
  "UPDATE \"Title\" SET status='published', \"durationS\"=60 WHERE slug='sintel-90-150-r2' OR slug LIKE 'grid-test-%';"
```

(friction 2026-09-26 "adb macos local network"). Accept "Allow USB debugging?" on the TV with "Always allow".

`Current Activity is null!` (friction 2026-10-01 "fire tv asleep").

### 0.8 Build and install the release build

Do not use `pnpm --filter @described/expo build:tv`. It runs an EAS cloud build, which cannot see the linked kit
(`link:../vega-media-kit`). Build locally instead. A release build has the JS bundle inside it, so it needs no Metro and no `adb reverse`.

```sh
cd ~/hackathon/described/apps/expo
export EXPO_PUBLIC_API_URL=http://<mac-ip>:4000
npx expo prebuild --clean          # writes android/; the release build allows plain HTTP only to <mac-ip>
npx expo run:android --variant release
```

- [ ] The build finishes and the app opens on the TV. If it does not open, run
      `adb shell monkey -p dev.moizp.described 1`.
- [ ] If the build fails in `:described-media-session` (Kotlin), add
      `"expo": { "autolinking": { "exclude": ["described-media-session"] } }` to apps/expo/package.json, run both commands
      again, and note it. Then skip check 14 (Alexa) and expect check 13 to use the key path only.
- [ ] `grep -c 'described:keyevent' android/app/src/main/java/dev/moizp/described/MainActivity.kt` prints `1`.
- [ ] `grep -A4 'android.intent.action.VIEW' android/app/src/main/AndroidManifest.xml` shows `android:scheme="described"`.
- [ ] Note the build time: ________ min.

If your Mac IP changes later, set `EXPO_PUBLIC_API_URL` again and repeat both commands. The IP is fixed into the build.

**Debug build instead (only if you need fast refresh).** A debug build loads JS from Metro on port 8081.
Check `lsof -i :8081` is empty first. If another project's Metro holds 8081, the TV runs **that** project's code with a
black screen (friction 2026-09-26 "expo port 8081 wrong bundle"). Then use `npx expo start --port 8082` and
`adb reverse tcp:8081 tcp:8082`, and repeat the reverse after every stick reboot.
